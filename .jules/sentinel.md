## 2024-05-18 - Prevent Command Injection in OS Shell Scripts
**Vulnerability:** OS-specific shell scripts (PowerShell, AppleScript) used `format!` macro for string interpolation to insert untrusted variables (like `prompt` and `title`) directly into the script string. This creates a command injection risk if user-controlled input isn't safely escaped.
**Learning:** Command Injection can happen when we call external shell environments (`powershell`, `osascript`, `zenity`) with dynamic input without properly using input parameters. While the `std::process::Command` arguments array protects against shell injection on its own arguments, executing a *script* means we're evaluating the script string as code.
**Prevention:** Instead of string interpolation or manual escaping, always pass variables securely via process environment variables (`.env("KEY", value)`) and access them natively within the script (e.g. `$env:KEY` in PowerShell or `system attribute "KEY"` in AppleScript).

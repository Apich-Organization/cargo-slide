## 2024-XX-XX - [Command Injection via External Script Evaluation]
**Vulnerability:** Found multiple instances where `std::process::Command::new` executes external GUI scripts (`osascript`, `powershell`) with user-provided `title` and `prompt` strings directly concatenated into the script content. While currently `title` and `prompt` might be mostly controlled by the application, any user-influenced string could break out of string quotes and execute arbitrary shell or OS commands (Command Injection). This is particularly dangerous as these prompts are used for sensitive secrets (PINs/passwords).

**Learning:** When generating dynamic OS-specific scripts (like AppleScript or PowerShell) from Rust using `format!`, simple string replacement (`replace("\"", "\\\"")` or `replace("'", "''")`) is often insufficient to guarantee security against command injection, especially in complex script environments. Passing inputs as arguments to a predefined script, or using established libraries for GUI dialogues, is much safer.

**Prevention:** Avoid dynamically constructing AppleScript or PowerShell scripts containing user inputs. If `std::process::Command` must be used, rely strictly on command-line arguments to pass user-controlled values instead of evaluating strings. Even better, use native cross-platform dialogue libraries instead of spawning external shell processes to display GUIs, or at the very least, heavily sanitize inputs using established methods if dynamic script execution is unavoidable.

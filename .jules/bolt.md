## 2024-10-22 - Optimizing Leptos 0.8 Reactivity with Memo::new
**Learning:** In Leptos 0.8, `Signal::derive` re-evaluates its closure on *every* read. When used for computationally expensive operations or extracting subsets of large structures (like `SlideDeck`), this causes severe performance bottlenecks. Additionally, calling `.get()` on signals holding large structures inside reactive contexts clones the entire structure.
**Action:** Always prefer `Memo::new(move |_| { ... })` over `Signal::derive` to cache results for expensive derivations. Ensure the returned type implements `PartialEq`. Furthermore, avoid using `.get()` on signals with large data structures unless a full clone is necessary; use `.with(|d| ...)` instead to read by reference or clone only what is needed.
